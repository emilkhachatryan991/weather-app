# Погода по городу

Веб-приложение: вводишь название города — показывает текущую температуру,
описание погоды и иконку. Данные — OpenWeather.

**Живая версия:** https://weather-app-ten-ashy-n0k9x45616.vercel.app

## Как устроено (и почему ключ не виден)

```
Браузер  ──►  /api/weather?city=Ереван   ──►  api.openweathermap.org
             (ваш же сайт, серверная         (ключ добавляется здесь,
              функция Vercel)                 на сервере)
```

- `index.html` — фронтенд, без сборки: чистый HTML/CSS/JS.
- `api/weather.js` — серверная функция Vercel. Только она знает ключ.

Браузер обращается **только к своему же адресу** `/api/weather`. Запрос в
OpenWeather делает сервер, ключ берётся из переменной окружения
`OPENWEATHER_API_KEY` и в браузер никогда не попадает — его не видно ни в
исходном коде страницы, ни во вкладке Network.

В репозитории ключа тоже нет: `.env.local` перечислен в `.gitignore`,
а коммитится только шаблон `.env.example` с плейсхолдером.

## Локальный запуск

```bash
npm i -g vercel
cp .env.example .env.local   # вписать свой ключ в .env.local
vercel dev                   # откроется http://localhost:3000
```

## Деплой

1. Залить репозиторий на GitHub.
2. На vercel.com → Add New → Project → импортировать репозиторий.
3. Settings → Environment Variables → добавить `OPENWEATHER_API_KEY`
   (значение — ваш ключ), окружения Production + Preview + Development.
4. Deployments → Redeploy.

## Обработка ошибок

Приложение не падает и не показывает технических деталей:

| Ситуация | Что видит пользователь |
|---|---|
| Город не найден (404) | «Город не найден. Проверьте название.» |
| Ключ не задан / неверный (401) | «Сервис временно недоступен. Попробуйте позже.» |
| Превышен лимит (429) | «Слишком много запросов. Подождите минуту.» |
| Нет сети | «Нет связи с сервером…» |

Последний город сохраняется в `localStorage`, поэтому при обновлении
страницы погода подгружается заново, а не теряется.

Источник данных: [OpenWeather](https://openweathermap.org/).
